第 0 节 全局视角: 示波器到底是什么
--------------------------------------------------------------------------------
示波器 = "把电压随时间的变化画出来"的仪器。它只有两个坐标轴:
  横轴可信  <-  相邻样本的时间间隔严格相等、严格已知 (采样钟是准的)
  纵轴可信  <-  码值到电压的换算是准的
再加一条工程要求: 显示要稳定 (否则看不了)。
这个题的所有设计, 全部围绕这三句话。后面每一节你都能对应回其中一条。

第 1 节 采样钟: 为什么必须定时器触发, 不能 ADC 自由运行
--------------------------------------------------------------------------------
先把名词定死:
  - 自由运行 (Continuous Conversion Mode = ENABLE): ADC 转完一个立刻转下一个,
    不等任何人。
  - 外部触发 (ExternalTrigConv + CONT=DISABLE): ADC 挂着等一个"开始转换"的
    脉冲, 来一个转一个。
  - TRGO (Trigger Out Gate? 不对, 是 Timer Output Trigger... 记"定时器输出
    触发"就行): 定时器把内部事件(比如更新溢出)路由到片内触发总线的一个信号。
    CR2.MMS = 010 就是"更新事件 -> TRGO"。

为什么自由运行不行? 因为横轴的"尺子"会变成橡皮筋:
  1) 间隔 = 一次转换的耗时 = (采样周期数 + 12.5) / ADC 时钟。这个数你知道,
     但它会被总线争用、时钟细节干扰, 不保证严格稳定。
  2) 你想改采样率, 只能改采样时间这种"副作用一堆"的参数。
  3) 20kHz 自由运行意味着 ADC 一直满负荷跑, DMA 也一直被塞数据。

定时器触发怎么解决:
  样本间隔 = TIM3 的溢出周期 = (PSC+1)(ARR+1)/72MHz。72MHz 来自晶振,
  精度 ±几十 ppm —— 间隔又准又稳。想换采样率就改 ARR, 一刀精确。
  本题: PSC=0, ARR=3599 -> 72MHz/3600 = 20kHz, 每样本 50us。

为什么用 TRGO 而不是"定时器中断里手动启动转换"?
  TRGO 是纯硬件连线 (TIM3 -> ADC 触发选择器, 片内), 0 CPU 参与Soft。
  软件路径 = 每秒 2 万次中断, 中断进出开销不说, 中断响应延迟的抖动会
  原样叠加到采样时刻上 —— 又把尺子弄成橡皮筋了。

为什么 TIM3 的时钟是 72MHz 不是 36MHz? TIM3 挂 APB1(36MHz), 但 F1 规定
  APB1 分频 != 1 时, 定时器时钟 x2, 所以还是 72MHz。这是 F1 特有规则。

  2) Continuous 开着时, TRGO 还起作用吗? 为什么?


第 2 节 为什么 DMA 循环模式, 深度 2048
--------------------------------------------------------------------------------
数据率算账: 20kHz x 2 字节 = 40KB/s。让 CPU 搬:
  - 轮询: 主循环死等, 什么都干不了;
  - 中断: 每秒 2 万次中断, 开销巨大。
DMA = "数据到了自动搬, 搬完连通知都不发"(我们一个中断都不开), 主循环只管
每 50ms 来拿一次现成的。

为什么 Circular (循环) 模式? 普通模式搬满就停; 循环模式写满自动回卷从头
覆盖 —— 等效一卷"磁带", 永远保存最近的一段历史。
  磁带长度 = 2048 / 20kHz = 102ms。
  写到哪了? 读 DMA1_Channel1->CNDTR (还剩多少没搬), 已写位置 head = 2048 - CNDTR。

为什么是 2048? 两个原因:
  1) 10ms/格 时一屏 = 100ms x 20kHz = 2000 个样本, 2048 刚好覆盖最大窗口;
  2) 2 的幂, 回绕取模可以用一次条件减法代替除法。

第 3 节 为什么快照要"停 TIM3 -> 拷贝 -> 重启" (防撕裂)
--------------------------------------------------------------------------------
场景: DMA 在环形缓冲里持续写, 你 CPU 现在开始读 2000 个样本。
读的过程中, DMA 可能正好把写指针绕回你正在读的区域 —— 你会拷到
"一半新一半旧"的数据, 拼接处出现一根和信号无关的竖线。
关键在于: 这根竖线的位置每帧都随机 -> 看起来像"偶发毛刺", 极难排查。

停表的原理: ADC 是"等触发才转"的。停掉 TIM3 = 没人发触发 = ADC 不转 =
DMA 不动 = CNDTR 冻结。这期间缓冲是死的, 随便读。
拷完重启 TIM3, 从冻结位置继续, 只丢几十 us 的数据, 对显示无感。

本质思想: 把"活的流数据"凝固成一份"死数组"(快照)。
后面触发、测量、画图全部在死数组上跑 —— 不用任何锁、任何同步技巧。
这是嵌入式处理流数据最常用的套路, 比中断里加临界区优雅得多。

自测: 为什么不停 ADC 而是停 TIM3? 停 ADC 行不行? (提示: HAL_ADC_Stop
  会把 DMA 也拆了, 重启要重新 Start_DMA, 开销和副作用大得多)


第 4 节 为什么要有触发, 为什么找"上升沿穿中点"
--------------------------------------------------------------------------------
先想不触发会怎样: 每 50ms 拍一张快照, 快照的起点(第 0 个样本)对应信号
的哪个相位, 完全是随机的。1kHz 方波周期 1ms = 20 个样本, 每帧起点差几个
样本, 波形就左右跳几个像素 —— 这就是"滚动"。像手动拍照手在抖。

触发 = 给每张快照定一个共同的起点: "信号上升穿过中点电平的那一刻"。
每帧都从这一刻开始画 -> 相位对齐 -> 波形叠加在同一个位置 -> 稳定。
这就是真示波器的核心机制 (题目原话"示波器的灵魂")。

三个细节的为什么:
  1) 为什么阈值用 (max+min)/2 而不是固定 1.65V?
     固定阈值: 信号幅度小了穿不过(永远找不到触发点), 大了穿越点会偏。
     用本帧的中点, 自适应幅度, 波形永远锁在最稳的位置。
  2) 为什么 Vpp < 40 码(约 33mV)就不触发?
     幅度太小, 噪声就会反复穿越中点, 触发点乱跳, 显示反而抖。
     小信号当直流处理, 画一条线, 更符合直觉。
  3) 为什么选上升沿?
     约定俗成。正弦/方波/三角都有唯一清晰的上升穿越点, 下降沿同理可用。

代价说明: 找触发点要扫一遍快照 O(n), 2000 个样本一次循环, 微秒级, 值。

自测: 触发点找到了, 但它在本帧靠后的位置, 画图时样本不够怎么办?
  (提示: 快照是环形数据的一段, 对 trace_n 取模回绕继续画, 时间上是连续的)


第 5 节 测频为什么这样写才过得了 <2% (本题最硬核的一节)
--------------------------------------------------------------------------------
频率 = 1 / 周期。测周期 = 数两个上升沿之间隔了几个样本, 乘 50us。

误差从哪来? 穿越点几乎总落在两个样本"之间", 而你只能用整数样本下标。
单周期 20 个样本, 误差 ±1 样本 = ±5% —— 题目要求 <2%, 单周期测法必死。

手段一: 线性插值 (把整数下标变成 0.1 样本分辨率)
  相邻两样本相对中点的带符号差 a(前), b(后), 上升穿越时 a<0, b>=0。
  穿越位置 = (i-1) + a/(a-b)。推导: 两个样本间电压是线性变化的,
  差值比例就是穿越点在两者之间的位置。
  例: 前样本比中点低 5 个码, 后样本高 5 个码 -> 穿越点在正中间 = 0.5。
  代码里的 x10 定点: (i-1)*10 + a*10/(a-b)。

手段二: 首尾沿平均 (关键! 不是相邻沿逐个平均)
  取本帧第 1 个和最后 1 个上升沿, 跨度 span 里包含 (nr-1) 个完整周期:
      频率 x10 = FS x 100 x (nr-1) / span
  为什么比"相邻沿逐个平均"好?
    相邻沿平均: 每个周期各付一次 ±1 样本量化误差, N 段平均后剩
      ±1/sqrt(N) 样本 -> N=10 时约 ±0.32 样本 = 1.6%, 还不够漂亮。
    首尾沿: 误差只付一次 (起点 ±0.5 + 终点 ±0.5 = ±1 样本),
      摊到跨度上 = ±1 / (N x 20) -> N=10 时 ±0.5%, N=100 时 ±0.05%。
  根本区别: 首尾沿把"每次测量的误差"变成"跨度两端的一次性误差"。

  另一个隐藏福利: 如果中点阈值有系统性偏差, 起点和终点的穿越点会
  同方向偏移, 在做差(span)时大部分抵消 —— 系统误差也掉了不少。

为什么用 x10 定点显示? 频率显示到 0.1Hz 就够, 用"放大 10 倍的整数"
表示, 显示时手动插小数点, 全程不碰 float。

第 6 节 占空比为什么也用中点
--------------------------------------------------------------------------------
占空比 = 高电平时间 / 周期。"高电平"的定义本身依赖阈值 —— 用哪个阈值
切, 高电平时间就不一样。所以必须和测周期用同一个中点阈值, 自洽:
  高电平时间 = 上升穿越 -> 下一个下降穿越
  整周期     = 上升穿越 -> 下一个上升穿越
两者都是插值后的 x10 定点, 相除 -> 0.1% 分辨率。
方波 50% 验收时, PA8 的 PWM 是精确 500/1000, 显示 50.0% 直接验证全链路。

第 7 节 为什么全程整数运算 (定点), 不用 float
--------------------------------------------------------------------------------
F103 的 Cortex-M3 没有 FPU, float 加减乘除全是软件库模拟, 慢一个数量级。
更实际的原因: 我们需要的显示精度只有 1mV / 0.1Hz / 0.1%, 定点完全够:
  电压: 码值 x 3300 / 4096 -> 毫伏 (整数)
  频率: 实际值 x10 -> "1000.0 Hz" 显示时插小数点
  占空比: 实际值 x10
这是"定点数"思想: 用放大 N 倍的整数表示小数。嵌入式测量领域的标准做法。
另外 Keil 的 MicroLIB 对 printf %f 支持有坑, 不碰最稳。


第 8 节 电压换算和自动居中
--------------------------------------------------------------------------------
12 位 ADC: 0~4095 线性映射 0 ~ VREF(3.3V), 1 码 = 3300/4096 = 0.806mV。
  vpp_mv = (max - min) x 3300 / 4096
误差来源(为什么 Vpp 读数和信号源差 ±50mV 内正常):
  - VREF 实际是板载 3.3V LDO, ±1% 就是 ±33mV;
  - 量化 ±1 码; 采样电容充电不完全还会再偏一点。

自动居中: y = 窗口中央 - (该点电压 - 信号中点电压) x 每格像素 / 每格电压
把 (max+min)/2 放屏幕中央 = 软件版的"垂直位置旋钮"。信号带直流偏置
也不用管, 波形永远在窗口里。真示波器这个旋钮是手拧的, 我们自动拧。

量程(软件换算): 每格电压从 1000mV 改成 500mV, 就是把同一份样本放大 2 倍
画 —— 波形变高, 测量数值不变。这就是"量程档位(软件换算)"的含义:
ADC 硬件量程永远是 0~3.3V, 换档只是显示缩放。


第 9 节 波形画法: 为什么"每列 min-max 包络 + 平坦列连线"
--------------------------------------------------------------------------------
一屏 200 列。1ms/格: 每列 1 个样本; 10ms/格: 每列 10 个样本。
一列内多个样本时只画一个点会怎样? 信号在一列内上上下下, 你只取最后一个,
画出来的是"假波形"(混叠假象)。正确做法是画这一列 min~max 的竖线段,
信号在这一列的所有起伏都被覆盖 —— 这正是真示波器"余辉"效果的数字化。

平坦列(该列 min==max)画单点, 并和前一列的 y 连线:
  斜坡上相邻列各画一个点, 中间会有空隙, 看起来是虚线;
  连线后是连续实线。竖直包络列取中点作为"当前高度"参与下一段连线。


第 10 节 为什么每帧全部重画 (清屏->网格->波形), 而不是只擦旧迹线
--------------------------------------------------------------------------------
全重画: 一帧 = 填 32000 像素 + 网格 + 迹线, FSMC 写入下 <10ms, 20FPS 没压力。
优点: 任何状态变化(时基/量程/触发)都不用做"UI 失效"管理, 代码最简单,
  不会出现"残留上一帧的残影"这类 bug。
缺点: 理论上有轻微闪烁(先黑再画), 20FPS 下不明显。
优化方向(留给你练): 保存上一帧每列的 y 范围, 只擦旧迹线列再画新迹线,
  网格只在换档时重铺一次。先求正确, 再求快。


第 11 节 按键: 为什么这样写消抖和事件
--------------------------------------------------------------------------------
你已经在按键实验里踩过的铁律, 这里说清因果:
  机械按键按下/松开瞬间, 触点会弹跳, 电平在几 ms 内来回跳几十次。
  消抖 = 电平变化后重新计时, 稳定满 20ms 才承认。
  *_last = *_now 必须放在"稳定且 != 上次确认值"的分支里:
    放前面 -> "检测到变化"的条件每圈都成立, 函数空转;
    不更新 -> 松手识别不了, 事件只触发一次还卡死。
事件位(s_key_evt) vs 电平 flag:
  电平 flag(比如 key0_flag=1)表达"现在按着", 主循环不消费就 while(1) 刷屏;
  事件位表达"发生过一次按下", 置位 -> 主循环处理 -> 清零, 一对一。
  示波器换档要的是"事件", 不是"电平"。

KEY_UP 为什么反着来: KEY0/KEY1 的一端接地, 靠上拉电阻, 按下 = 低;
KEY_UP 的一端接 VCC, 靠下拉电阻, 按下 = 高。硬件接法决定软件电平,
复制粘贴按键代码时这里必错, 单独拎出来记。


第 12 节 为什么 20FPS, 节拍怎么实现
--------------------------------------------------------------------------------
人眼 >20Hz 就感觉连续; LCD 全重画 <10ms; 50ms 节拍 = 留足余量 + 省电。
更快只是徒增闪烁和功耗。
实现: HAL_GetTick() 差值 >= 50 才出帧, 到点自动刷新 —— 非阻塞,
主循环还能顺手扫按键。绝不 HAL_Delay(50) 死等(把主循环堵死)。


第 13 节 为什么必须 HAL_ADCEx_Calibration_Start
--------------------------------------------------------------------------------
F1 的 ADC 内部用一组小电容做逐次逼近, 电容之间有制造失配, 表现为
读数整体偏移几十个码。上电后、启动转换前, 跑一次校准, 芯片自动测出
失配并修正。只此一次, 之后一直有效。这是 F1 特有的必做步骤(F4 没有)。


第 14 节 为什么用 PA8 出自测信号
--------------------------------------------------------------------------------
验收要求输入 1kHz 方波/正弦。正弦要信号发生器, 方波可以自己造:
TIM1_CH1 (PA8) PWM: 72MHz/72 = 1MHz 计数, 数 1000 个 = 1kHz, CCR=500 = 50%。
为什么值得做:
  1) 没有发生器也能验收;
  2) 源是精确已知的(1000.0Hz / 50.0%), 给你的测频算法一张标准答案 ——
     算法错了立刻能看出来, 而不是怀疑信号源。
为什么用 TIM1: 它是高级定时器, HAL_TIM_PWM_Start 会自动置 MOE 位
(主输出使能), 高级定时器不置这个位 PWM 引脚没输出 —— 这是 TIM1 特有的坑,
普通定时器(TIM2/3/4)没有这一步。

自测题参考答案
--------------------------------------------------------------------------------
第 0 节: 横轴可信 —— 采样钟是整个系统的时间基准。
第 1 节: 1) 72MHz/50kHz = 1440, ARR = 1439。2) 不起作用。CONT=1 时 ADC
  转完立刻转下一个, 根本不进入"等触发"状态, 触发信号被无视。
第 2 节: % 运算对 2 的幂会被编译器优化成一次位与(AND), 快; 非 2 的幂是
  真除法, 几十倍慢。这是"缓冲深度取 2 的幂"的通用理由。
第 3 节: 停 ADC 也行, 但 HAL_ADC_Stop 会连带卸掉 DMA 映射, 重启要重新
  Start_DMA + 可能重新校准, 开销大副作用多; 停 TIM3 只是没人触发,
  ADC 和 DMA 原地冻结, 重启一条指令。
第 4 节: 画图索引对 trace_n 取模回绕。快照本质是环形流的一段, 回绕后
  时间依然连续, 波形无缝。
第 5 节: 1) 1ms/格 = 10ms 窗口 = 10 个周期, 约 10~11 个上升沿,
  首尾沿误差 ±1/200 = ±0.5%。2) 见题面括号。
第 6 节: 偏大。阈值抬高 -> 下降穿越推迟 -> 高电平时间被算长;
  上升穿越也推迟但幅度不同。总之两个测量必须同阈值才自洽。
第 15 节: 迟滞: 若无迟滞, Vpp 恰好在换档边界附近时, 噪声让它一会儿
  满足升档一会儿满足降档, 量程疯狂来回跳。迟滞让两个方向的判定错开,
  中间存在一个"维持原档"的缓冲带。
